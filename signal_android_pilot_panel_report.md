# Signal Android pilot panel report

Generated by `build_signal_android_pilot_panel.py`. No regression or interaction model was estimated.

This file constructs a canonical dataset. It does **not** establish that unmatched quality classes are clean.

## A. Construction methodology

- Universe: Signal Android CSIQ quality CSVs, six versions (`2016-1` … `2021-1`).
- One class-version row per top-level `QualifiedName` that appears in the quality file.
- One longitudinal row per top-level `QualifiedName` that exists in two consecutive versions.
- Smell counts are attached by exact key match to that **same** version's PMD CSV.
- Unmatched smell status is stored as `status_known=0` and **NULL counts**, never as zero.
- Candidate rules only: `DataClass`, `ExcessiveMethodLength`, `ExcessiveParameterList`, `MutableStaticState`, `LawOfDemeter`, `GodClass`.
- Cyclomatic/NCSS/Cognitive/NPath rules are not encoded as predictors.
- A sensitivity zero-filled file was **not** created.

## B. Exact class join methodology

```
smell_key = Package + '.' + basename(File)   # extension stripped
match iff smell_key == quality.QualifiedName
```

No fuzzy match, no inner-class projection, no package-only match. Test-path PMD rows join if and only if the key equals a quality `QualifiedName`.

## C. Top-level filtering methodology

The classifier is identical to `csiq_pilot_audit.py`:

- Exclude `<Package>`, `<Method>`, `<Field>`, `<Anonymous>`, other `<...>` rows.
- Exclude names with no `.` (project/commit header).
- Exclude inner/nested types whose parent segment starts with an uppercase letter (`Outer.Inner`).
- Retain only `top_level`.

This is a QualifiedName-shape rule, not a guess about source files.

## D. Longitudinal matching methodology

Consecutive snapshots only: 2016-1→2017-1, …, 2020-1→2021-1.
Match = exact `QualifiedName` string equality on top-level classes present in both quality files.
`WMC_t1` is read from the later quality file. `delta_WMC = WMC_t1 - WMC_t` when both are numeric.

## E. Smell-status-known semantics

| status_known | count | Meaning |
| ---: | --- | --- |
| 1 | integer ≥ 0 | Class key is in that version's PMD export. 0 means this candidate rule had no violation. It does **not** mean the class has no other PMD rules. |
| 0 | NULL | Class key is not in the PMD export. Smell status is unknown. **Not clean. Not zero.** |

Construct-specific `*_status_known` flags equal `smell_status_known` because one `design.xml` dump covers all six rules.

Worked examples preserved in the file:

- PMD observed, DataClass absent → `DataClass_count=0`, `DataClass_status_known=1`
- No PMD class record → `DataClass_count` empty, `DataClass_status_known=0`

Class-version observations with fully known smell status: **3953** of 5870 (67.34%).

## K. Anomalies discovered

1. PMD-observed classes are a selected sample: they had at least one `design.xml` violation of any rule. A class with zero of the six candidates is not clean.
2. LawOfDemeter dominates joint-presence tables. That is co-occurrence, not an interaction.
3. Early-year PMD paths often lack `src/main`, so test/main tagging remains coarse. Tests were not dropped.
4. `ConversationAdapter`-style unmatched PMD keys from the previous audit are outside this quality-driven panel and stay out.
5. No sensitivity zero-fill file. Command.txt shows PMD was aimed at the repo, but the CSV does not list analyzed-but-clean files. That is not enough to recode unknown as 0.

## M. Variables that MUST NOT be used for the first WMC model

- `GodClass_count_*` — WMC-contaminated (`WMC_contaminated=true`).
- Binary `LawOfDemeter` — near-constant among PMD-observed classes.
- Any cyclomatic / NCSS / CognitiveComplexity / NPath / AvoidDeeplyNestedIfStmts rule.
- `CouplingBetweenObjects` / `ExcessiveImports` together with `CBO_t`.
- Manufactured zeros for `smell_status_known=0`.
- Configuration dummies interpreted as 'interaction effects' without a Model A vs Model B comparison.
- `delta_WMC` labeled as software corrosion.

Remaining issue before modeling: the estimand must be restricted to PMD-observed top-level classes (`smell_status_known_t=1`), or a separately justified (currently unjustified) complete-universe assumption is required. That is a sample-definition choice, not a license to fill zeros.
